# F4: Context & Memory Systems

## Findings

### [1] Claude Code uses a dual-layer memory system: CLAUDE.md (user-written persistent instructions) + Auto memory (LLM-written learnings), both loaded at session start
- quote: "Each Claude Code session begins with a fresh context window. Two mechanisms carry knowledge across sessions: CLAUDE.md files: instructions you write to give Claude persistent context, Auto memory: notes Claude writes itself based on your corrections and preferences"
- url: https://docs.anthropic.com/en/docs/claude-code/memory
- source_type: primary
- published: unknown (current docs)
- confidence: high

### [2] Claude Code auto memory is capped at 200 lines or 25KB of MEMORY.md, with detailed notes pushed to topic-specific files loaded on-demand
- quote: "The first 200 lines of MEMORY.md, or the first 25KB, whichever comes first, are loaded at the start of every conversation. Content beyond that threshold is not loaded at session start. Claude keeps MEMORY.md concise by moving detailed notes into separate topic files."
- url: https://docs.anthropic.com/en/docs/claude-code/memory
- source_type: primary
- published: unknown (current docs)
- confidence: high

### [3] CLAUDE.md supports hierarchical scoping (managed policy > user > project > local), path-specific rules via `.claude/rules/`, and file imports via `@path` syntax
- quote: "CLAUDE.md files can live in several locations, each with a different scope... Scope rules to specific file types with .claude/rules/"
- url: https://docs.anthropic.com/en/docs/claude-code/memory
- source_type: primary
- published: unknown (current docs)
- confidence: high

### [4] Repomix (26.9k GitHub stars, v1.16.0 as of June 2026) compresses entire repositories into single AI-friendly files using Tree-sitter for AST-aware code compression
- quote: "The --compress option uses Tree-sitter to extract key code elements, reducing token count while preserving structure."
- url: https://github.com/yamadashy/repomix
- source_type: primary
- published: Jun 29, 2026
- confidence: high

### [5] Long-context best practice: place long data at the top of prompts, queries at the bottom — this improves response quality by up to 30% in tests
- quote: "Put longform data at the top: Place your long documents and inputs near the top of your prompt, above your query, instructions, and examples... Queries at the end can improve response quality by up to 30% in tests, especially with complex, multi-document inputs."
- url: https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/long-context-tips
- source_type: primary
- published: unknown (current docs)
- confidence: high

### [6] Claude Code's context compression (/compact) re-injects project-root CLAUDE.md from disk after compaction, but nested CLAUDE.md files are lost until the relevant subdirectory is accessed again
- quote: "Project-root CLAUDE.md survives compaction: after /compact, Claude re-reads it from disk and re-injects it into the session. Nested CLAUDE.md files in subdirectories are not re-injected automatically; they reload the next time Claude reads a file in that subdirectory."
- url: https://docs.anthropic.com/en/docs/claude-code/memory
- source_type: primary
- published: unknown (current docs)
- confidence: high
