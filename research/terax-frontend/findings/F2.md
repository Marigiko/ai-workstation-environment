# F2: Terax Plugin/Extension System

## Findings

### [1] Terax has no formal extension/plugin API — this is an explicit product decision
- quote: "Also skip if you expect a plugin ecosystem—there's no extension API, so you're dependent on upstream for every feature."
- url: https://starlog.is/articles/developer-tools/crynta-terax-ai
- source_type: secondary (independent technical review)
- published: 2026-05-24
- confidence: high

### [2] ROADMAP explicitly rules out IDE-scale extension marketplaces
- quote: "Extension marketplaces at IDE scale... Arbitrary UI or behavior extensions will not [be built]."
- url: https://github.com/crynta/terax-ai/blob/main/ROADMAP.md
- source_type: primary (official project roadmap)
- published: 2026 (continuously updated)
- confidence: high

### [3] AI tool/skill bundles as installable packages are on the longer-horizon roadmap
- quote: "AI tools / skills as installable bundles"
- url: https://github.com/crynta/terax-ai/blob/main/ROADMAP.md
- source_type: primary (official roadmap)
- published: 2026
- confidence: medium (listed under "longer horizon", no timeline or spec)

### [4] Custom agents are user-definable via Settings with per-agent system prompts and tool subsets
- quote: "Define your own agents in Settings -> Agents. Each agent has: Its own system prompt. Its own tool subset (you can grant any subset of the composer tools)."
- url: https://terax.app/docs/ai/plans-and-subagents
- source_type: primary (official documentation)
- published: 2026
- confidence: high

### [5] Custom agents persist as JSON in the app data directory — no source-code changes needed
- quote: "Custom agents are stored in terax-ai-agents.json in the app data directory."
- url: https://terax.app/docs/ai/plans-and-subagents
- source_type: primary (official documentation)
- published: 2026
- confidence: high

### [6] Snippets/skills are user-created reusable prompt fragments callable via #handle or /slash commands
- quote: "Snippets are user-defined reusable prompts registered via the UI (Settings -> Agents or the slash-command picker). They appear as /my-snippet in the AI input bar. No code change needed — they are stored via snippetsStore and resolved in slashCommands.ts."
- url: https://langlabs.io/crynta/terax-ai
- source_type: secondary (technical analysis)
- published: 2026-05-09
- confidence: high

### [7] Extending agent tools requires source-code modification — no end-user plugin API
- quote: "Extending agent tools: Add a new file in src/modules/ai/tools/, implement the tool definition with Zod schema (Vercel AI SDK tool() helper), and register it in tools/tools.ts."
- url: https://langlabs.io/crynta/terax-ai
- source_type: secondary (technical analysis)
- published: 2026-05-09
- confidence: high

### [8] TERAX.md provides project-level agent memory — human-readable, git-diffable, no vector DB
- quote: "Terax loads TERAX.md from the workspace root as agent memory, the same way Claude Code reads CLAUDE.md... It is just a Markdown file you keep in your repo."
- url: https://terax.app/docs/ai/sessions-and-memory
- source_type: primary (official documentation)
- published: 2026
- confidence: high

### [9] Sub-agents have isolated conversation state — no shared memory with parent agent
- quote: "Sub-agents share the keychain but not conversation state. runSubagent.ts spawns an independent agent with its own message history. It does not inherit the parent's prior messages."
- url: https://langlabs.io/crynta/terax-ai
- source_type: secondary (technical analysis)
- published: 2026-05-09
- confidence: high

### [10] Terminal agent hooks for Claude Code, Codex, and Gemini CLI integration
- quote: "Detect Claude Code in any PTY and route its state into the Terax notification surface... Claude Code hooks - one-click installer for terminal-agent integration."
- url: https://terax.app/docs/ai/plans-and-subagents
- source_type: primary (official documentation)
- published: 2026
- confidence: high

### [11] No MCP (Model Context Protocol) support exists in Terax
- quote: (absence — MCP is not mentioned in README, docs, source code, or roadmap)
- url: https://github.com/crynta/terax-ai
- source_type: primary (official repository)
- published: 2026-07-07
- confidence: high

### [12] BYOK architecture supports any OpenAI-compatible endpoint — enables local model integration
- quote: "BYOK providers: OpenAI, Anthropic, Google (Gemini), Groq, xAI (Grok), Cerebras, OpenRouter, DeepSeek, Mistral, plus any OpenAI-compatible endpoint... Local / offline: LM Studio, MLX, Ollama."
- url: https://github.com/crynta/terax-ai/blob/main/README.md
- source_type: primary (official README)
- published: 2026
- confidence: high

### [13] Active community with multiple forks — no community extension ecosystem
- quote: (8.3K stars, 885 forks, 521 commits, Discord community — but no marketplace, registry, or extension sharing platform)
- url: https://github.com/crynta/terax-ai
- source_type: primary (official repository metrics)
- published: 2026-07-07
- confidence: high

### [14] Tauri plugin integration is source-code-level only — requires Cargo.toml, lib.rs, and capability JSON changes
- quote: "New plugins typically need: 1. Cargo.toml dependency 2. .plugin(...) call in lib.rs run() 3. capability entry in default.json"
- url: https://github.com/crynta/terax-ai/blob/main/TERAX.md
- source_type: primary (official architecture doc)
- published: 2026
- confidence: high
