# F1: Terax Core Architecture

## Findings

### [1] Terax is an open-source AI-native terminal emulator / ADE (Agentic Development Environment) built on Tauri 2 + Rust backend and React 19 + TypeScript frontend, shipping as a ~7-8 MB binary with no telemetry, no account, and BYOK (Bring Your Own Key) AI.
- quote: "Terax is a lightweight open-source terminal (ADE) built on Tauri 2 + Rust and React 19. A native PTY backend with a WebGL renderer, an agentic AI side-panel that runs against your own keys or fully local models, plus a code editor, file explorer, source control with a git graph, and a web preview pane built in. About 7-8 MB on disk. No telemetry. No account."
- url: https://github.com/crynta/terax-ai
- source_type: primary
- published: unknown (README is living document)
- confidence: high

### [2] Terax uses a two-process architecture: Rust owns all OS access (PTY, filesystem, git, shell spawn, network, secrets) while the React webview never touches the filesystem, processes, or shells directly — all host operations go through Tauri `invoke()` IPC calls.
- quote: "Terax is two processes: the Rust backend (`src-tauri/`) and the webview frontend (`src/`). Rust owns all OS access: PTY, file system, git, shell spawn, network, secrets, workspace authorization. The webview never touches the FS, processes, or shells directly. Every host operation goes through an `invoke()` call to a command registered in `src-tauri/src/lib.rs`."
- url: https://raw.githubusercontent.com/crynta/terax-ai/main/docs/architecture/two-process-model.md
- source_type: primary
- published: unknown
- confidence: high

### [3] Terminal rendering uses xterm.js with a WebGL renderer backed by a renderer slot pool (max 5 slots) — hidden terminal leaves with foreground jobs keep live grids parked with rendering paused via `display:none`, and an idle `DormantRing` (1 MiB buffer, no terminal reset on overflow) handles overflow for leaves whose slot was stolen.
- quote: "TerminalStack keeps one mounted xterm per tab via `useTerminalSession` + `pty-bridge`. Renderer slots are pooled (`rendererPool.ts`, max 5): a hidden leaf with a foreground job keeps its live grid parked with rendering paused via `display:none`; an idle hidden leaf releases its slot but the buffer is retained and serialized lazily only when another leaf steals it. The `DormantRing` (1 MiB, no terminal reset on overflow) buffers bytes only for leaves whose slot was stolen or never bound."
- url: https://raw.githubusercontent.com/crynta/terax-ai/main/TERAX.md
- source_type: primary
- published: unknown
- confidence: high

### [4] The PTY backend uses `portable-pty` for cross-platform native PTY support with shell integration via OSC 7 (cwd tracking) and OSC 133 A/B/C/D (prompt boundary markers), supporting zsh, bash, pwsh, fish, and cmd — on Windows, ConPTY requires a `SPAWN_LOCK` mutex around open+spawn and each child is assigned to a Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` to prevent orphan processes.
- quote: "Native PTY backend via `portable-pty` (zsh, bash, pwsh, fish, cmd)... ConPTY on Windows requires `SPAWN_LOCK` (Mutex) around `openpty + spawn_command` in `session.rs`... Each ConPTY child is also assigned to a per-session Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`."
- url: https://raw.githubusercontent.com/crynta/terax-ai/main/TERAX.md
- source_type: primary
- published: unknown
- confidence: high

### [5] The tech stack is: Tauri 2, Rust, `portable-pty`, React 19, TypeScript, Vite, xterm.js, CodeMirror 6, Vercel AI SDK v6, Tailwind v4, shadcn/ui, Zustand — with codebase composition of ~79.5% TypeScript, ~18.3% Rust, ~1% CSS.
- quote: "Tech stack: Tauri 2, Rust, `portable-pty`, React 19, TypeScript, Vite, xterm.js, CodeMirror 6, Vercel AI SDK v6, Tailwind v4, shadcn/ui, Zustand."
- url: https://github.com/crynta/terax-ai

### [6] The AI subsystem is BYOK with cloud providers (OpenAI, Anthropic, Google/Gemini, xAI/Grok, Cerebras, Groq, DeepSeek, Mistral, OpenRouter, plus any OpenAI-compatible endpoint) and local/offline providers (LM Studio, MLX, Ollama) — agent loop built on Vercel AI SDK v6 `streamText` with sub-agents (explore, code-review, security, general) that cannot recurse, tool approval gates for mutating operations, and edit diffs that open in side-by-side tabs before applying.
- quote: "BYOK providers: OpenAI, Anthropic, Google (Gemini), Groq, xAI (Grok), Cerebras, OpenRouter, DeepSeek, Mistral, plus any OpenAI-compatible endpoint. Local / offline: LM Studio, MLX, Ollama. Agentic workflow: plans, sub-agents, project memory via `TERAX.md`, file read / write / edit / multi-edit / grep / glob, bash with approval gating, background processes."
- url: https://raw.githubusercontent.com/crynta/terax-ai/main/TERAX.md
- source_type: primary
- published: unknown
- confidence: high

### [7] Security is defense-in-depth with five trust boundaries: IPC boundary (Tauri capabilities allowlist), filesystem boundary (deny-list on `.env*`, `.ssh/`, credentials, etc. applied on both read and write), network boundary (AI HTTP proxy with SSRF and DNS-rebinding defenses via IP classification and pinning), secret-storage boundary (OS keychain via `keyring` crate, never disk/localStorage), and terminal escape-sequence boundary (OSC 7/133/777 parsed but never blindly trusted).
- quote: "The main trust boundaries are: IPC boundary, File-system boundary, Network boundary, Secret-storage boundary, Terminal escape-sequence boundary... The deny-list in `security.ts` applies on both read and write. Never bypass it."
- url: https://raw.githubusercontent.com/crynta/terax-ai/main/docs/architecture/security-model.md
- source_type: primary
- published: unknown
- confidence: high

### [8] Terax explicitly positions itself as NOT a full IDE replacement — it is opinionated about being "terminal-first" with AI as a native primitive, and deliberately scopes out heavy IDE features (full LSP integration, debuggers, refactoring engines), notebook workspaces, package manager UIs, extension marketplaces, and telemetry/accounts.
- quote: "What Terax is not: Not a full IDE replacement. Heavy IDE features that overlap with VS Code / Cursor / Zed are out of scope... The product is opinionated: terminal-first, AI as a primitive (not a sidebar), lightweight always, cross-platform without compromise."
- url: https://raw.githubusercontent.com/crynta/terax-ai/main/ROADMAP.md
- source_type: primary
- published: unknown
- confidence: high

### [11] Terax has a planned roadmap feature for "AI agent meta-orchestration" — the ability for Terax's own agent to spawn and manage external coding agents like Claude Code, OpenCode, Codex, and Gemini CLI — with already-shipped agent detection that reads OSC 777 markers from these tools and routes notifications through a unified router.
- quote: "AI agent meta-orchestration (Terax agent spawning and managing external coding agents like Claude Code / OpenCode)... Terminal detection is Rust-side (`pty/agent_detect.rs`) on the PTY reader's byte filter, armed on `OSC 133;C;<cmd>` or self-armed by the marker, emitting `terax:agent-signal` transitions (`started`/`working`/`attention`/`finished`/`exited`)."

- source_type: primary
