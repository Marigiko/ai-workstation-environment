## Data Flow: Telegram → System → Telegram

```
1. User sends message via Telegram
2. Telegram Bot (n8n webhook) receives message
3. n8n workflow parses command:
   - /prompt <text> → Forward to Auto Orchestrator
   - /status → Query Workspace API
   - /approve <task_id> → Approve task
   - /commit <message> → Git commit
4. Auto Orchestrator receives task:
   - Architect agent plans (qwen2.5-coder:7b)
   - Decomposes into sub-tasks
   - Distributes to specialized agents
5. Agents execute via MiMo/ai-workstation:
   - Each agent uses its configured model
   - Headroom wraps all inputs for compression
   - Results stored in Workspace API
6. Notification sent back via Telegram
7. User can approve/reject/continue
```

## API Contracts

### Gateway API (ai-workstation :8000)
```
POST /chat                      # Pipeline chat with context
POST /v1/chat/completions       # OpenAI-compatible
GET  /v1/models                 # List models
POST /sessions                  # Create session
GET  /sessions/{id}             # Get session
POST /context/index             # Index project context
POST /router/resolve            # Resolve routing
POST /skills/{name}/execute     # Execute skill
```

### Workspace API (:8080)
```
POST /workspaces                # Create workspace
POST /sessions                  # Create session
POST /sessions/{id}/messages    # Add message
POST /tasks                     # Create task
POST /tasks/{id}/approve        # Approve task
GET  /notifications             # List notifications
POST /notification-rules        # Create rule
WS   /ws?workspace_id=X         # Real-time events
```

### Telegram Bot API
```
/prompt <text>                  # Send task to orchestrator
/status                         # Check system status
/status <task_id>               # Check task status
/approve <task_id>              # Approve task
/reject <task_id>               # Reject task
/commit <message>               # Git commit
/worktrees                      # List worktrees
/worktree <name>                # Switch worktree
/models                         # List available models
/model <name>                   # Switch model
/agent <name>                   # Switch agent
/auto                           # Toggle auto mode
```

## Error Handling

### Retry Strategy
- Telegram messages: 3 retries with exponential backoff
- Model calls: 2 retries with fallback to next model
- Task execution: Configurable retry count per agent

### Fallback Chain
```
Primary Model → Fallback Model → Local Model → Error Notification
qwen2.5-coder:7b → phi3:mini → qwen2.5-coder:1.5b → Telegram error
```

### Error Notifications
- Task failure → Telegram notification with error details
- Model timeout → Telegram notification with alternative
- System error → Telegram notification with status

- APIs: 100 requests/minute per key
